## Part A: cache 模拟器

### 实现简述

缓存采用组相联映射（Set-Associative Mapping）结构，主要参数包括组索引位数s、每组中的缓存行数E和块偏移位数b。每个缓存行包含有效位valid、标记位tag和最近使用时间last_use_time用于实现LRU替换策略。初始化时，根据输入参数动态分配2^s个组，每组含E个缓存行。处理内存访问时，解析地址计算组索引和标记位，在对应组中查找是否命中：若命中，则更新最近使用时间；若未命中且组内无空闲行，则依据LRU策略选择last_use_time最小的行进行替换，并更新其标记位和最近使用时间。每次访问后，统计命中次数、未命中次数和替换次数，以此优化缓存性能。通过这种方法，实现了高效的缓存管理和数据访问优化。

## Part B: 矩阵乘法优化

### 亮点

1.分块：将运算矩阵分块计算，分块大小通过调参决定  
2.寄存器重用：将中间结果储存在寄存器中减少内存的读取操作  

#### 我认为的最优秀的实现排序

### case1

Case1的算法主要结合了分块和寄存器重用技术。首次仅采用分块优化，性能提升有限（得分约1.3）。随后结合了case0的寄存器优化思路。

缓存未命中分析  
空间局部性：采用8x8的分块策略，每次处理的数据集中在小范围内，提高了空间局部性。  
时间局部性：内部循环中重复使用从A和B加载到寄存器中的值(tmpa, tmpb0至tmpb7)来更新tmpc0至tmpc7，减少了不必要的重复加载。  
每个块大小为32字节，假设reg类型是4字节（32位），每个块可以存储8个reg类型的元素。给定矩阵A、B、C均为16x16大小，这意味着每次处理一个8x8的小矩阵块需要64个reg类型的元素，即需要8个连续的块来存储这些数据。  
对C的访问产生2 × 16 = 32次cache miss，因为每次分配8个寄存器并按内存顺序读取。  
对A的访问产生16 × 16 = 256次cache miss，由于每次读取为跨行读取，导致每次都会miss。  
对B的访问产生2 × 16 = 32次cache miss，与C类似。总共理论上为320次cache miss。  
冷启动未命中较少，冲突未命中也较少，因为直接映射（E=1）虽然可能导致某些冲突，但实验结果显示这种冲突不多。容量未命中同样较少，由于良好的数据局部性。  
寄存器未命中分析  
在每次处理8x8块时，需要同时保持大量临时变量在寄存器中。每个i值需要16个寄存器（8个用于tmpc0到tmpc7，1个用于tmpa，以及8个用于tmpb0到tmpb7）。对于每个ii值，最多需要处理8个i值，这意味着理论上最多需要128个寄存器，远超硬件提供的32个寄存器，导致寄存器溢出和寄存器未命中。  
寄存器未命中计算公式为（（8 × 9 + 8）× 8）× 4 = 2560次，每次计算块内一行时分配9个寄存器，计算8行，同时分配C矩阵对应的寄存器，最后分成了4块。  
第一次尝试采用了寄存器复用，发现A和B同时取的时候很容易取到同一set的组，导致大量miss。研究分块计算后，发现可以将一行的C同时计算，按行计算则取B是连续的，可以优化两个矩阵。这种方法的缺点是需要申请大量的寄存器，但总体性能远优于原始方法。

### case2和case3

算法首先将矩阵A、B和C划分为多个4x4的小矩阵块，然后使用两个嵌套的for循环遍历矩阵的所有可能的起始点（row_start和col_start），每次迭代处理一个4x4的块。row_start从0开始，以步长BLOCK_SIZE增加，直到小于矩阵A的行数m。类似地，col_start从0开始，以步长BLOCK_SIZE增加，直到小于矩阵B的列数p。对于每个4x4块，初始化16个累加器(sum00至sum33)用于存储乘积累加的结果。通过第三个for循环遍历矩阵A和B的对应行和列，对于每个元素进行乘积计算并累加到相应的累加器中。在这个过程中，检查是否超出矩阵的实际维度，并根据需要加载相应的值。  
计算完成后，将累加器中的结果写回到矩阵C中相应的位置。当row_start + 1, row_start + 2, 或row_start + 3超过矩阵A的行数m时，不执行相关的计算和写回操作。同样地，当col_start + 1, col_start + 2, 或col_start + 3超过矩阵B的列数p时，也不执行相关的计算和写回操作。  

在优化case2和case3时，最初采用了与case1相同的寄存器重用策略，虽然得到了4左右的得分，但由于矩阵规模较大，导致了较多的寄存器未命中。为了改善这一情况，尝试了矩阵分块的方法，并通过调整不同的分块大小进行实验。初期尝试并未取得理想效果，甚至在采用二次分块方法后，加速比下降至2左右。进一步分析表明，关键在于如何有效利用缓存，尤其是在处理较大矩阵时避免频繁的内存访问。

![Case2](./imgs/2.png)

最终发现，当BLOCK_SIZE设置为4时性能最佳，尽管加速比仍不理想。深入分析后认识到，在这种方法中，矩阵A、B和C的元素在内层循环中被多次访问，但这些元素未能得到有效缓存，每次处理新的块时都需要重新从内存读取A和B的相关元素，导致了冗余的内存访问。为此，改进方案是每次计算4x4块的乘积时，初始化16个变量（如c00, c01, c02, ... c33）来存储当前块的部分和。遍历矩阵A的列和矩阵B的行，将A的每一行与B的每一列进行乘法运算并将结果累加到对应的变量中。为了减少内存访问，从矩阵A中加载当前块的4行，从矩阵B中加载当前块的4列，然后逐步累加计算结果并写回矩阵C。

![Case3](./imgs/3.png)

这种改进方法充分利用寄存器存储中间计算结果，直接在寄存器中累加计算结果而不是频繁地将中间结果存储到内存中，从而显著提高了计算效率。由于寄存器访问速度远快于内存访问，这种方法不仅减少了内存访问次数，还通过重复使用存储在寄存器中的矩阵A和B的多个元素，提升了缓存命中率。相比之前的方法，尽管也缓存了A的每一行，但未能充分利用A和B之间的关系，导致缓存局部性利用不足，而新方法则有效地解决了这一问题，实现了超过8倍的加速比。这种方法通过更高效地利用寄存器和缓存结构，显著提升了整体性能。

case2和case3虽然矩阵大小不一样，但本质上还是解决相近大小矩阵乘法的问题，算法是可以套用的。
